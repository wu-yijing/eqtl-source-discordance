## 2. 潜藏错误（非本次改动，是 2026-10-05 那次修复自身留下的）：`MANIFEST_REPAIR_20261005.md`

| | |
|---|---|
| 该文件记录的 | `c9f649049ed0d075c1549496521f1f23680b3d757cc98c88ee8421c20d52f79b` |
| 实际（LF，入库字节） | `a663faf322d5db7880ffacf3c323b72ae79295002e713ce30ac3c4c12c18e6ee` |
| 该文件是否被本次改动 | **否**（`git diff HEAD` 只显示 `toolchain/versions.txt` 两行新增） |

**成因**：`git log` 显示该文件自 `21bf727` 起再无提交，即**内容没变过**，那么不符只能来自
**当初写下这一行时哈希算的是另一份内容** —— 也就是那次修复先生成了 `MANIFEST.sha256`，
随后又编辑了这份说明文件，两者在同一个提交里落地，而没有重算哈希。

**已排除的解释**：不是行尾。该文件实测不含 CR（LF，入库字节即工作副本字节）；按 CRLF 重算
也不等于记录值（`7046c7f5…`）。所以这不是"记录了规范化之前的 CRLF 工作副本"那个老问题，
而是修复动作自身的一次漏算。

**这正是第 13 道门禁存在的理由**：在它之前，`docs/audit_notes/*/MANIFEST.sha256` **没有任何
门禁校验**，所以这类漏算可以长期存在而不被任何人发现 —— 本次是它第一次被一个自动检查抓住。
